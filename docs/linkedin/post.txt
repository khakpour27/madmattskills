Your AI agent isn't the problem. Your workflow is.

For months my AI coding sessions went the same way: a vague ask, an eager plan, "Phase 1: database, Phase 2: API, Phase 3: UI", tests written after the fact to match the code, and a context window that got dumb halfway through.

The fix wasn't a bigger framework. It was the engineering fundamentals we already know, written down so the agent follows them every time.

So I packaged that workflow into an open-source Claude Code skill: madmattskills.

☀️ Day shift (me + the agent)
→ Grill: the agent interviews me one question at a time, each with a recommended answer, until we share the same design
→ PRD: user stories, which modules change, how it's tested, what's out of scope
→ Issues: thin vertical slices that each end in something clickable, with dependencies mapped so they can run in parallel

🌙 Night shift (agents, AFK)
→ One issue per fresh session: failing test first, minimal code, refactor, commit
→ Review in a clean context with my coding standards pushed in

Then I do the QA, and anything I find becomes a new issue.

It draws on Brooks, Fowler, The Pragmatic Programmer, Ousterhout, and Matt Pocock's "Workflow for AI Coding" workshop. Old books, new agents.

Install once, use it in every repo:
/plugin marketplace add khakpour27/madmattskills

👉 https://github.com/khakpour27/madmattskills

It's plain markdown and bash, so fork it and make it yours. If it saves you from one more "Phase 1: database" plan, a ⭐ helps others find it.
